This article discusses about how to use Last Write Wins strategy to resolve write conflicts in Multi-Master Replication and how to handle the extreme scenarios which LWW could not cover.
At first, the candidate introduces that they simply overwrite the older one using the value of later update based on LWW approach. However, the interviewer mentions the situation that two users update different fields of the same item which could cause write conflicts. The candidate gives the fix which is splitting the record into separate keys, so that users could update their own keys which would never interfere with each other. This approach is simple and efficient.
Besides that, the interviewer gives another scenario that how to handle the conflicts on updating the same field from two operations. The candidate proposes a tiered approach which depends on the criticality of the field. For non-critical fields, the data loss is acceptable, so they keep the LWW and let the operators redoes to recover updates. For critical fields, they will introduce versioned conditional updates instead of LWW. In this way, the application layer will reject the write whose version has changed and refresh.
In the end, the interviewer wants to know how to prevent the system losing data caused by NTP offset between two machines because LWW never check machine clocks. The candidate says that they will actively monitor NTP offset between two data centers and make sure the gap under 5ms which is a safe window for most of cases. But for use cases requiring absolute ordering, they will give up LWW and adopt consensus algorithm to guarantee globally ordering.
To summarize, the interviewer and the candidate talk about the approaches to resolve write conflicts occurring under different circumstances.
