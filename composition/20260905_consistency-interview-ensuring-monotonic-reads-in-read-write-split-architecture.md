This article is talk about how to guarantee read consistency in read-write splitting architecture. The classic problem is read-write splitting plus load balancing would break Monotonic Read, in this pattern, two requests would be routed to different replications, so the interviewer wants to know routing approach which the candidate choses to guarantee that same users always reads from the same replica.
The candidate gives the user-ID-based hash routing which would ensure user's requests hit the same replica. However, this approach cannot cover case when replica fails, the interviewer would like to know guarantee monotonic reads in this case. The candidate says that they simply fall back to the master, but it might increase pressure of the master when replica is unavailable.
And then the interviewer hints another approach which is use replication position. The candidate explains the mechanism of this design and gives the solution to handle checking timeout. The timeout means the replica will always check its replication position to receive the position the user last saw. The candidate proposes that they use the maximum timeout which is 200ms to limit the wait loop, once the loop exceeds 200ms, and it will fall back to the master immediately.
To summarize, the candidate progressively gives different solutions to guarantee monotonic read, these solutions could cover various scenarios.
